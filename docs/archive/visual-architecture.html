Visual Architecture Guide — End-to-End System Explanation

The Big Picture

System Overview

📱

Customer

Sends WhatsApp message to business number (e.g., "Hi, I need a 3BHK apartment")

🌐

Meta Cloud API

Receives message, sends webhook POST to your server with routing info (which client + which customer)

⚡

FastAPI Server

Processes message, fetches client config from database, generates AI reply, sends back via Meta

🗄️

Supabase PostgreSQL

Stores client configs (prompts, tokens), conversation history (AI memory), and extracted leads (CRM data)

🧠

Gemini 3.8 Flash

Generates natural AI replies using client's custom prompt + business knowledge + conversation context

💼

CRM Dashboard

Shows extracted leads (name, budget, HOT/WARM/COLD) with "Open WhatsApp" button — NO chat history stored here

🎯 Key Concept: ONE Server, MANY Clients

Your FastAPI server handles ARVANA + PropMaster + ShopKaro + 20 more clients simultaneously. Each client has their own AI prompt, business knowledge, and Meta API token stored in the database. When a message arrives, the server looks up the client config using phone_number_id and processes everything accordingly. Complete isolation, zero mixing.

Step-by-Step

Complete Message Flow (Real Example: ARVANA)

1

📱 Customer Sends WhatsApp Message

A prospect interested in ARVANA's services sends a WhatsApp message to +91-9876543210 (ARVANA's business number):

Message: "Hi, I'm interested in lead automation for my real estate business"
⬇
2

🌐 Meta Sends Webhook to Your Server

Meta's servers receive the message and immediately send a webhook POST request to your server:

// POST https://your-server.com/webhook
{
  "entry": [{
    "changes": [{
      "value": {
        "metadata": {
          "phone_number_id": "123456789"  ← ARVANA's business number ID
        },
        "messages": [{
          "from": "919988776655",  ← Customer's phone
          "text": { "body": "Hi, I'm interested in..." }
        }]
      }
    }]
  }]
}

Key Point: Meta tells you phone_number_id (which client) and from (which customer). This is how routing works!

⬇
3

🔍 Server Looks Up Client Config in Database

Your FastAPI server extracts phone_number_id = "123456789" from the webhook and queries the database:

-- SQL Query:
SELECT * FROM clients WHERE phone_number_id = '123456789';

-- Returns:
{
  "id": "arvana-uuid-001",
  "business_name": "ARVANA",
  "phone_number_id": "123456789",
  "access_token": "EAAx...arvana_token",
  "system_prompt": "You are ARVANA's AI assistant...",
  "business_knowledge": { "services": ["WhatsApp bots", "CRM"] }
}

Why? The server needs to know WHICH client this message belongs to, so it can use THEIR custom AI prompt and THEIR Meta token for the reply.

⬇
4

💾 Load Conversation History (AI Memory)

The server fetches the last 10 messages from the messages table for this customer:

-- Get last 10 messages for this conversation:
[
  { "role": "user", "content": "Hi, I'm interested in..." }
]

// If customer messaged before, history includes previous messages
// This is HOW AI remembers context!

Why Store Messages? So AI can remember what the customer said before. Without this, AI would forget and repeat questions!

⬇
5

🧠 Generate AI Reply Using Gemini

The server sends THREE things to Gemini 3.8 Flash:

// What Gemini receives:

1. SYSTEM PROMPT (from database):
"You are ARVANA's AI assistant. Help businesses automate WhatsApp leads.
Ask ONE question at a time. Never invent services we don't offer."

2. BUSINESS KNOWLEDGE (from database):
{ "services": ["WhatsApp bots", "CRM dashboards"], "pricing": "₹15K-50K/month" }

3. CONVERSATION HISTORY (from messages table):
[
  { "role": "user", "content": "Hi, I'm interested in lead automation..." }
]

// Gemini generates:
"reply": "Hi! 👋 Great to hear you're interested in lead automation!
Are you currently managing WhatsApp leads manually, or using any automation tools?"

Why This Works: Gemini knows ARVANA's personality (from prompt), real facts (from knowledge), and conversation context (from history).

⬇
6

📤 Send Reply via Meta Graph API

The server sends the AI reply back to the customer using ARVANA's Meta API token:

// POST to Meta Graph API:
POST https://graph.facebook.com/v19.0/123456789/messages
Authorization: Bearer EAAx...arvana_token  ← ARVANA's token!

{
  "messaging_product": "whatsapp",
  "to": "919988776655",  ← Customer's phone (from webhook)
  "text": { "body": "Hi! 👋 Great to hear you're interested..." }
}

Result: Customer receives instant WhatsApp reply in under 5 seconds! ⚡

⬇
7

💾 Save AI Reply to Messages Table

The server saves the AI's reply to the database so it's available for next time (conversation memory):

-- INSERT into messages table:
{
  "conversation_id": "conv-uuid-123",
  "sender": "ai",
  "content": "Hi! 👋 Great to hear you're interested...",
  "timestamp": "2026-11-11T18:00:00Z"
}
⬇
8

📊 Extract Lead Data (Structured JSON)

A SECOND Gemini call analyzes the full conversation and extracts structured data:

// Gemini extracts (using ARVANA's extraction_schema):
{
  "name": null,  ← Not provided yet
  "business_type": "Real Estate",
  "monthly_leads": null,
  "budget": null,
  "timeline": null,
  "classification": "NEW",  ← Not enough info to classify yet
  "ai_summary": "Real estate business interested in lead automation"
}

Why? This structured data goes into the CRM dashboard. Much easier to read than scrolling through WhatsApp chats!

⬇
9

🎯 Save Lead to CRM Database

The extracted data is saved to the leads table:

-- UPSERT into leads table:
{
  "client_id": "arvana-uuid-001",
  "customer_phone": "919988776655",
  "industry": "Real Estate",
  "budget_range": null,
  "classification": "NEW",
  "ai_summary": "Real estate business interested in lead automation",
  "updated_at": "2026-11-11T18:00:00Z"
}

// As conversation continues, this record UPDATES (not duplicates!)

Done! Lead now appears in your CRM dashboard. You can filter by HOT/WARM/COLD and call the promising leads.

🔥 Key Insight: Messages vs Leads Tables

messages table: For AI memory only. NOT shown in CRM. Stores last 10 messages so AI can remember context.

leads table: For CRM dashboard. Shows extracted structured data (name, budget, classification) + "Open WhatsApp" button. You click the button → WhatsApp app opens → You see the FULL chat there.

How Multi-Tenant Works

Routing: How Server Finds Right Client & Customer

💡 The Routing Question You Asked:

"We have so many clients and each client has so many customers messaging them. How does our server know which CLIENT and which CUSTOMER to send the reply to?"

Visual Answer: Meta Tells You Everything!

Server

/webhook

📩 Incoming Webhook from Meta:

"phone_number_id": "123456789"
"from": "919988776655"

📩 Another Webhook from Meta:

"phone_number_id": "987654321"

↓ Server queries database:

SELECT * FROM clients
WHERE phone_number_id = '987654321';

↓ Returns PropMaster's config

↓ Reply sent using:
- PropMaster's system_prompt
- PropMaster's access_token
- Customer: 918877665544

🔑 The Answer: phone_number_id is the Routing Key!

Step 1: Meta's webhook includes phone_number_id (which business number received the message)
Step 2: Your server does: SELECT * FROM clients WHERE phone_number_id = '...'
Step 3: Database returns THAT client's prompt, token, and knowledge
Step 4: Server uses THAT client's data to generate and send the reply

Result: No mixing. No confusion. Each message is automatically routed to the correct client!

From Zero to Live

Client Onboarding Process (15 Minutes)

📋 Pre-Call: Send Intake Form 5 min

Before scheduling the Zoom call, send a form asking:

  • Business name
  • WhatsApp number for automation (must be fresh SIM or disconnected from regular WhatsApp)
  • Industry type (Real Estate, E-Commerce, etc.)
  • Do you have a Meta Business Account? (Yes/No)

⚠️ Critical: The Phone Number Rule

A phone number CANNOT be used on regular WhatsApp app AND Meta Cloud API at the same time. Client must either use a fresh SIM or disconnect from regular WhatsApp (chat history on that number will be lost). Ask this BEFORE the call to avoid surprises!

👤 Step 1: Client Adds You as Partner 5 min (Zoom)

During the Zoom call, guide the client (screen share):

  • Go to business.facebook.com/settings
  • Click Partners → Add Partner
  • Enter YOUR Meta Business Portfolio ID (you tell them this number)
  • Select their WhatsApp Business Account (WABA) from dropdown
  • Grant "Manage WhatsApp Account" permission
  • Done! They share ZERO passwords with you. Official Meta partner model.

⚙️ Step 2: You Configure Backend 10 min (After Call)

In YOUR Meta Business Manager (client is off the call now):

  • Create a System User for this client (e.g., bot-propmaster)
  • Assign the client's shared WABA to this System User
  • Grant whatsapp_business_messaging and whatsapp_business_management permissions
  • Generate a permanent access token (never expires)
  • Get the phone_number_id from Meta dashboard (their business number's ID)
  • Register YOUR webhook URL (https://your-server.com/webhook) for their WABA

🗄️ Step 3: Add Client to Database 2 min

Run SQL in Supabase SQL Editor:

INSERT INTO clients (
    business_name, phone_number_id, waba_id,
    access_token, status, system_prompt,
    business_knowledge, extraction_schema
) VALUES (
    'PropMaster Realty',
    '1234567890',           -- from Meta dashboard
    'waba_id_here',         -- from Meta dashboard
    'EAAx...token...',      -- generated in Step 2
    'ACTIVE',
    'You are the property inquiry assistant for PropMaster Realty...',
    '{"areas": ["Anna Nagar", "T Nagar"], "price_start": "50L"}',
    'Extract: name, property_type, budget, timeline, classification'
);

✅ Step 4: Test & Go Live 2 min

Send a test WhatsApp message to the client's business number. Verify AI responds correctly with client-specific personality. Show the client → Mind blown! 🤯

Done. Client is LIVE. Total time from intake form to live bot: 15 minutes.
