Step-by-Step Breakdown

The 10-Step Pipeline

Every step that happens from "customer sends Hi" to "lead appears in your CRM dashboard". This is what process_incoming_message() does in main.py.

1

📨 Customer Sends WhatsApp Message

Customer sends a normal WhatsApp message to the business number. Meta's servers pick it up and deliver it to YOUR server via a webhook POST request.

// What Meta sends to YOUR server (POST /webhook): { "object": "whatsapp_business_account", "entry": [{ "changes": [{ "value": { "metadata": { "phone_number_id": "123456789" }, "messages": [{ "from": "919876543210", "text": { "body": "Hi, I need a 3BHK in Anna Nagar" } }] } }] }] }
2

🔍 Identify Which Client This Message Belongs To

This is the multi-tenant magic. The phone_number_id tells us WHICH business number received this message. We look it up in the database to fetch EVERYTHING about that client.

# db.py — Fetches client config from Supabase SELECT * FROM clients WHERE phone_number_id = '123456789'; # Returns ONE row with ALL client data: { "id": "uuid-propmaster-001", "business_name": "PropMaster Realty", "phone_number_id": "123456789", "access_token": "EAAx...their_meta_token", "status": "ACTIVE", "system_prompt": "You are the property assistant...", "business_knowledge": {"areas": ["Anna Nagar", "T Nagar"]}, "extraction_schema": "Extract: name, property_type, budget..." }
3

🔴 Kill Switch Check

If the client's status is "SUSPENDED" (they stopped paying), the message is immediately dropped. The bot goes silent. No AI call, no WhatsApp reply. Zero cost to you.

# main.py line 132-134 if client.get("status") == "SUSPENDED": logger.warning(f"Client {client['business_name']} is SUSPENDED.") return {"status": "suspended"} # Done. Nothing happens.
4

💾 Save Customer Message to Database

The customer's message is saved to the messages table with sender = "customer". This builds the conversation history that AI uses for context.

# Saved to messages table: { "conversation_id": "conv-uuid-123", "sender": "customer", "content": "Hi, I need a 3BHK in Anna Nagar", "timestamp": "2026-11-11T10:30:00Z" }
5

🧠 Load Conversation Memory

Fetches the last 10 messages from the database. This is HOW the AI remembers what the customer said before. Without this, every message would feel like a brand new conversation.

# What AI receives as context: [ {"role": "user", "content": "Hi, I need a 3BHK in Anna Nagar"}, {"role": "assistant", "content": "Great choice! Are you looking for Apartment or Villa?"}, {"role": "user", "content": "Apartment, budget around 80 lakhs"} // AI now KNOWS: 3BHK, Anna Nagar, Apartment, 80L budget ]
6

🤖 Generate AI Reply (Gemini 1.5 Flash)

Gemini receives THREE things from the database (all client-specific):
① system_prompt — The personality and rules (e.g. "You are a property assistant...")
② business_knowledge — Real facts (areas served, price ranges, inventory)
③ conversation history — What the customer already said

# ai.py — What goes to Gemini: SYSTEM INSTRUCTION (from DB): "You are the property inquiry assistant for PropMaster Realty. Ask only ONE question at a time. Never invent property listings or prices." BUSINESS KNOWLEDGE (from DB, appended): {"areas": ["Anna Nagar", "T Nagar"], "min_price": "50L"} CONVERSATION HISTORY: User: "Hi, I need a 3BHK in Anna Nagar" GEMINI REPLY: "Great! Anna Nagar is a wonderful area! 🏠 Are you looking for an Apartment or an Independent House?"
7

📤 Send Reply via Meta Graph API

The AI reply is sent back to the customer using the CLIENT'S access token (not yours!). Each client's reply goes through their own Meta credentials.

# whatsapp.py — Sends via Meta Graph API v19.0: POST https://graph.facebook.com/v19.0/{client.phone_number_id}/messages Authorization: Bearer {client.access_token} { "messaging_product": "whatsapp", "to": "919876543210", "type": "text", "text": { "body": "Great! Anna Nagar is wonderful! 🏠..." } }
8

💾 Save AI Reply to Memory

The AI's response is saved alongside the customer's message. Next time the customer messages, Step 5 loads BOTH messages, so AI remembers the full conversation.

9

📋 Extract Lead Data (Structured JSON)

A SECOND Gemini call analyzes the full conversation and extracts structured data using the client's extraction_schema from the database.

# What Gemini returns as JSON (real estate example): { "name": null, "property_type": "3BHK Apartment", "preferred_location": "Anna Nagar", "budget": "80 Lakhs", "timeline": null, "classification": "WARM", ← Budget specified but no timeline yet "ai_summary": "Looking for 3BHK apartment in Anna Nagar, budget ~80L" }
10

📊 Upsert Lead to CRM Database

The extracted data is saved (or updated) in the leads table. If this customer messaged before, their existing lead record is UPDATED (not duplicated). This is what your CRM dashboard reads from.

# leads table — ready for CRM dashboard: { "client_id": "propmaster-uuid", "customer_phone": "919876543210", "service": "3BHK Apartment", "budget_range": "80 Lakhs", "classification": "WARM", ← 🟡 "ai_summary": "3BHK in Anna Nagar, ~80L budget", "custom_data": { ... full extracted JSON stored here } }

🤔 Why Can't We Use Fewer Tables?

🏢 clients — "WHO is this for?"

Without it: Your server wouldn't know which business received the message, what AI prompt to use, or which Meta token to send replies with. You'd have ONE hardcoded bot for ONE business forever.

With it: ONE server handles ARVANA + PropMaster + ShopKaro + 20 more clients. Each has their own prompt, knowledge, and Meta credentials.

💬 conversations — "WHICH chat thread?"

Without it: If 3 customers message PropMaster, all their messages would be jumbled in one pile. AI would mix up who said what.

With it: Each customer has their OWN conversation thread. Customer A's chat and Customer B's chat are completely separate. UNIQUE(client_id, customer_phone) ensures no duplicates.

📝 messages — "WHAT was said?"

Without it: AI has no memory. Every message is a brand new conversation. Customer says "3BHK" and AI asks "What are you looking for?" again.

With it: AI loads last 10 messages, remembers the entire context, and continues naturally. This IS the AI's brain memory.

🎯 leads — "WHAT did we learn?"

Without it: You'd have to read 50 WhatsApp conversations manually to figure out who's a hot lead and who's just browsing.

With it: AI extracts structured data automatically. You open the CRM dashboard and instantly see: "5 HOT leads, 12 WARM, 30 COLD" — sorted, scored, and summarized.

🔐 Security: What's Missing (Fix Before Deploy)

  • Row Level Security (RLS) is OFF — Right now, if someone guesses your Supabase URL, they could query ALL clients' data. Fix: Enable RLS policies in Supabase.
  • /leads endpoint has NO authentication — Anyone who finds your server URL can call GET /leads and see all leads. Fix: Add API key or JWT auth.
  • Access tokens stored in plaintext — Meta API tokens are stored unencrypted in Supabase. Acceptable for now (server-side only), but encrypt for production.
  • CORS is set to allow all origins — allow_origins=["*"] should be restricted to your CRM dashboard domain only.
